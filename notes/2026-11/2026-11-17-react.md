# ReAct: interleaving thoughts and tool calls

**Paper:** Yao et al., 2022, "ReAct: Synergizing Reasoning and Acting in Language Models" ([arXiv:2210.03629](https://arxiv.org/abs/2210.03629)), code and prompts at [react-lm.github.io](https://react-lm.github.io/)

## Idea
Instead of reasoning first and acting later (or acting with no reasoning at all), the model writes a free-form *Thought*, then an *Action*, then reads the *Observation*, and repeats. Formally the action space is just extended with language, so a "thought" is an action that doesn't touch the environment but updates the context.

## Why it matters
This is basically the loop behind most tool-calling agents today. The paper's ablations make the trade-off concrete: chain-of-thought alone hallucinates facts, while acting alone loses track of what it has already learned.

## Concrete detail
The Wikipedia tool is deliberately weak: only `search[entity]` (first 5 sentences of the page), `lookup[string]` (next sentence containing the string, like Ctrl+F), and `finish[answer]`. The best HotpotQA/FEVER results came from combining ReAct with CoT-SC: fall back to self-consistency if ReAct doesn't finish within 7 (HotpotQA) or 5 (FEVER) steps, and fall back to ReAct if the CoT-SC majority answer appears in fewer than n/2 samples.

## What I'd try
Port that two-way fallback to a modern function-calling agent and measure how often the "low-agreement → use tools" switch fires on questions the model already knows.
